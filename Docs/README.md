# Docs — Portfolio knowledge base

Research and source-of-truth content for Sina Oshaghi's personal portfolio (Payload CMS).
Every doc here carries **YAML frontmatter** so it can be validated, indexed, and later seeded
into Payload collections. Decisions behind this structure live in [Decisions.md](Decisions.md).

**Audience lens:** mixed — *personal brand first*. The site must work for recruiters, clients
and collaborators, but story and identity come before any single conversion goal. All benchmark
analyses are written through this lens.

**Language:** the site is bilingual (English default, Persian). Docs are authored in English;
any value the site will display carries a `<key>_fa` twin (see Conventions).

## Conventions

- **Status lifecycle** — `draft` → `review` → `ready`. `ready` means safe to seed into Payload.
- **Open questions** — anything I inferred rather than sourced is marked directly under the
  statement as a numbered callout:
  `> ❓ **Q3 — Confirm:** …`
  Every doc with callouts ends with a **Review checklist** mirroring them. A doc cannot be
  `ready` while any `❓` remains. Statements taken from the resume are tagged `(resume)`.
- **Machine-owned tables** — anything between `<!-- index:start -->` and `<!-- index:end -->`
  is regenerated by `pnpm docs:index` from frontmatter. Edit the frontmatter, not the table.
- **Templates** — files prefixed `_` (e.g. `_template.md`) are copied, never edited in place
  for content. Changing a template means updating `scripts/docs/lib/schema.ts` too.
- **Persian values** — `<key>_fa` holds the Persian version of `<key>` (e.g. `title_fa`,
  `summary_fa`). Missing `_fa` values fall back to English on the site.
- **Screenshots are local-only** — `Benchmarks/*/assets/` is gitignored. The `.md` analysis is
  the durable record; screenshots are working material on this machine.
- **Slugs** — benchmarks: the site's domain in kebab-case (`linear.app` → `linear-app`);
  experience: the company folder name in lowercase; projects: kebab-case working title.

## Workflow

### Sending a URL (benchmark)
Say which bucket — **Content** or **Design** — or send it and I'll ask. Then:

```bash
pnpm docs:benchmark <url> <content|design>
```

creates `Benchmarks/<Type>/<slug>.md` from the template with the frontmatter pre-filled
(title, url, slug, date, language, generator), captures `desktop.png` (1440), `mobile.png`
(390) and `desktop-fold.png` into `Benchmarks/<Type>/assets/<slug>/`, and regenerates the
index. I then write the analysis, score it against the [Rubric](Benchmarks/Rubric.md), and
fill `summary` (the one-line takeaway shown in the index). Every ~3 benchmarks,
[Synthesis.md](Benchmarks/Synthesis.md) is updated and any pattern that changes the site's
shape is reflected in [Content-Model.md](Content-Model.md).

### Sending a project (experience)
Send the project name, company, and Figma link(s). I:

1. Check it against [Inventory.md](Experience/Inventory.md) (featured? priority?).
2. Read the Figma file via the Figma MCP (screens, flows, components).
3. Write `Experience/<Company>/<project-slug>.md` from `Experience/_template.md` as a case
   study: context → problem → role → process → solution → outcome → learnings.
4. Export key frames to `Experience/<Company>/assets/<project-slug>/`.
5. Run `pnpm docs:index` so the company page and the Experience index update.

## Tooling

| Command | What it does |
|---|---|
| `pnpm docs:benchmark <url> <content\|design> [--slug s] [--no-screenshot] [--force]` | Intake a benchmark URL (see above) |
| `pnpm docs:index [--check]` | Regenerate every machine-owned table from frontmatter; `--check` fails if anything would change |
| `pnpm docs:validate [paths...] [--strict]` | Validate frontmatter against `scripts/docs/lib/schema.ts`; `--strict` turns warnings into errors |
| `pnpm docs:check` | `docs:index --check` + `docs:validate` — run before committing |

Scripts live in `scripts/docs/`; see its README for details.
